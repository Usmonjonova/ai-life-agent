# Memory System

## Purpose

Memory exists to make future interactions more useful, not to store everything.

## Memory categories

### Stable profile

Examples:

- preferred name;
- planning preferences;
- preferred communication style.

### Goals

- goal statement;
- reason;
- target;
- priority;
- status.

### Constraints

- recurring commitments;
- known time limitations;
- user-defined boundaries.

### Preferences

- reminder preferences;
- preferred focus session length;
- planning style.

### Learned patterns

Examples:

- user tends to underestimate large tasks;
- user often completes difficult work in the morning.

These are hypotheses and should have evidence.

### Temporary context

Examples:

- today's schedule;
- temporary deadline;
- current project.

Temporary information should expire or become inactive when appropriate.

## Memory quality rules

Every memory should ideally have:

- source;
- created_at;
- updated_at;
- confidence;
- status;
- optional expiry.

## Memory principle

Do not infer sensitive personal attributes unnecessarily.

Do not store raw personal data when an aggregate or derived value is sufficient.

## User transparency

Future versions should provide:

> What do you know about me?

and

> Why are you recommending this?

The user should be able to inspect and correct important remembered information.
